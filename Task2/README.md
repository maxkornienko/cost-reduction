# Task2. Целевой процесс онбординга магазина

Целевой процесс подключения купленного магазина. Номенклатуру сопоставляет ИИ-сервис SKU Matching, а товаровед проверяет только сомнительные позиции.

## Документы

| Файл | Содержание |
|---|---|
| [verification-point.md](verification-point.md) | Точка верификации и участие человека в процессе |
| [diagrams/onboarding-to-be.bpmn](diagrams/onboarding-to-be.bpmn) | Диаграмма процесса в нотации BPMN 2.0 (TO-BE), открывается в Camunda Modeler или на bpmn.io |

## Ключевые решения

- Две параллельные ветки – оборудование и товары. Выездов нет: сотрудник магазина подключает всё по инструкции удалённого ИТ-инженера.
- Маппинг делает облачная ИИ-модель по API, встроенная в наш процесс (PaaS).
- Точка верификации: уверенность 98% и выше – автоматически; 95–98% – сравнение цен, расхождение больше 30% уходит товароведу; ниже 95% – товароведу.
- Цели: трудозатраты на открытие точки – не больше пяти дней, ошибки маппинга – не больше 3%. Цель по ошибкам и пороги проверяются на ретро-данных.
